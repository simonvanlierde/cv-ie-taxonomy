Accessibility statement

This page covers the interactive map at simonvanlierde.com/cv-ie-taxonomy. Simon van Lierde builds it and is responsible for this statement.

Using the map

You can:

  • read each rating as a letter and an ink weight, not only as a colour. In high-contrast mode and in print, the ratings also get textures;
  • open every task with the keyboard. Each task is a named button. The scene list has a button for each scene, so the keyboard reaches every scene;
  • close a task's details with Esc. The focus goes back to the task that opened it. While the details have the focus, the left and right arrow keys move to the next task in the same scene;
  • read all the ratings as text in Plain table. Esc closes it and puts the focus back on its button;
  • open a source's full reference with the keyboard. Esc closes the reference first, then the details;
  • skip the moving drawing: if your device asks for reduced motion, the fan no longer follows the scroll, and each scene shows its finished drawing at once;
  • use a dark theme, which follows your device's setting;
  • use it on a phone. Each scene lists its tasks as buttons, and a task's details open as a sheet that keeps the keyboard focus inside it until you close it;
  • read the result of Analyse photo as text. It sits in a status region, so screen readers can announce it when it arrives.

How accessible the map is

The map aims to meet WCAG 2.2 at level AA, the usual standard for accessible websites.

Its conformance is not assessed: nobody has checked it against every WCAG 2.2 rule yet. No outside expert has tested it.

Known problems

None are recorded. The checks below leave gaps, so there may be problems we haven't found. Please tell us about any you meet.

Tell us about a problem

If any part of the map is hard or impossible for you to use, email code@duinlab.nl. Tell us what you tried to do, what happened, and which browser and assistive technology you use, if any. If you have a GitHub account, you can also open an issue.

We'll reply within 10 working days. If you need the research in another format, ask and we'll send it.

How we check

These automatic checks run on every proposed change:

  • axe-core scans each scene, an open task, the What if? editor, each photo panel and the phone layout for WCAG 2.0, 2.1 and 2.2 level A and AA problems.
  • Tests use the keyboard on the tasks, the scene list, the plain table and the source references. They check that Esc closes each one, and where the focus goes when a task or the plain table closes.
  • Tests check reduced motion and high-contrast mode in a real browser.
  • Tests check the contrast of the drawing's colours, its labels and the status text, in the light and the dark theme.

Automatic tools find only some problems, so passing them doesn't mean there are none. These checks also leave gaps:

  • The browser tests run in Chromium only, not in Firefox or Safari.
  • axe scans the light theme only.
  • axe can't measure the contrast of text that sits over the drawing's grid.
  • There is no record of a test by hand with a screen reader.

The map needs HTML, CSS and JavaScript to work.
